# 戦場

既存のワールド選択で「戦場」を選ぶか、戦場のセッションに参加します。参加者は赤・青の少ない側へ入り、人数が同じなら赤になります。人数の上限は追加していません。

平坦な1マップに、障害物、両チームの復活地点、拠点A・B・C、一人乗りの戦車を各チーム側に1台ずつ配置します。拠点に一方のチームだけが2秒間とどまると所有権が変わります。両チームがいる間は占領が進みません。所有権が変わっても戦闘は続きます。

体力は100です。歩兵の射撃は1発25、戦車は1発50のダメージを与えます。射撃間隔は歩兵400ms、戦車900ms、射程は14mです。味方には当たりません。照準の方向にいる最も近い敵をサーバーが判定し、障害物を越えた命中は認めません。戦車を破壊する別の体力は設けず、搭乗者の体力で生死を判定します。

倒されると操作できなくなり、死亡から3秒経過後の更新で復活します。復活回数の制限や試合終了はありません。復活地点が戦車などで塞がれているときは、マップ内で元の地点に近い安全な位置を選びます。安全な位置がマップ内に一つもない場合だけ、空くまで待ちます。

## 操作

| 操作 | 2D俯瞰 | 3D |
| --- | --- | --- |
| 移動 | WASD・矢印キー。画面下の方向ボタンも使用可 | WASD・矢印キー。視点を基準に移動 |
| 照準 | マップ上のマウス位置・指の位置 | 画面をクリックしてマウス操作を開始し、視点を動かす |
| 射撃 | クリック・射撃ボタン・Spaceの長押し | 操作開始後のクリック・Spaceの長押し |
| 戦車の乗降 | 2.5m以内でEまたは画面の乗降ボタン | 同左 |

チーム、体力、復活までの秒数、拠点所有権、搭乗状態、ボットの識別を両表示に出します。2D・3Dの切り替えでは戦況や戦車の搭乗を解除しません。戦場では通常の「ついていく」、人を置き直す操作、飛行、座席による位置変更を戦闘移動に使いません。

降車位置は、戦車や障害物と重ならず、壁を越えずに出られる周囲の位置をサーバーが選びます。周囲に出られる位置がなければ搭乗を保ちます。搭乗中に接続を切った場合は戦車を解放し、再参加した人が動ける安全な歩兵位置を残します。

## ボット

初期状態は0体です。セッションを作成した人だけが画面のボタンから追加・削除でき、暫定上限は6体です。所有者情報のない固定セッションでは追加できません。人数による自動補充、ボットの戦車操作、難易度の選択はありません。

ボットは拠点を目標に移動し、見通せる敵を射撃します。既存の2D歩行は近くの障害物を避ける方式だったため、ボットには共有の障害物データを使う有限グリッド探索を追加しました。静的地形、共有アセット、共有システム、戦車を避けます。経路は定期的に探し直し、到達できないときは別の拠点を試します。障害物を無視した移動や、移動先への瞬間移動は行いません。

## 状態と同期

`shared/battlefield.ts`にマップ、状態、入力の検証、衝突・射線・経路探索を置き、`server/battlefield.ts`でセッションごとの戦闘を更新します。人の識別と参加資格は既存セッションを使い、戦闘用の参加手続きは追加しません。人とボットは同じ移動、射撃、被弾、死亡、復活、占領処理を通ります。

戦車は既存のバイク型に`battlefield-tank`の種類を登録して接続します。通常のアイテムメニューや共有システムからは作成できず、位置変更・片付け・通常の運転要求では書き換えられません。戦闘状態にある搭乗者だけが動かせます。退出・死亡・削除・ワールド変更・セッション破棄で搭乗と入力を解放します。

既存の初回スナップショットと部屋向け配信で戦況を送ります。戦場で新しく接続するときは参加者間の直接位置配信を使わず、以前のワールドで確立済みの直接配信も表示には採用しません。通常のavatar・place2d・follow要求で戦闘位置を書き換えることはできません。途中参加や同期の再接続は現在の状態を受け取り、試合を初期化しません。サーバーの再起動にまたがる戦況の保存は行いません。

## 検証

`npm run test:battlefield`で時刻と乱数を固定した戦闘・入力・翻訳テストを実行します。`npm run test:battlefield:integration`は既存の開発用認証、使い捨てDB、暗号化した部屋通信を通します。試験プロセス間の通信だけで時刻を進め、公開の操作メッセージから時刻や乱数は変更できません。

`npm run test:session-actions`には戦場の初回受信と更新受信による復元の検証を含みます。`npm run test:battlefield:browser -- <Playwrightのモジュール> [ブラウザの実行ファイル]`は既存の依存とPostgreSQLに加え、導入済みのPlaywrightを使います。使い捨てサーバーとViteを起動し、実際の2D・3D画面で移動、照準、射撃、搭乗、表示切り替え、両表示のボット識別を検証します。ページを離れてホーム接続も切り、再参加後の状態を通常の受信処理で復元します。Playwrightの依存追加は行っていません。

`npm run benchmark:battlefield -- 60`で、人8体と人2体＋ボット6体を別々のサーバープロセスで60秒ずつ測定します。既存のPostgreSQL試験環境と、通常の依存パッケージが必要です。50ms間隔で同じ移動パターンと射撃を送り、サーバー更新時間、人の入力の検証・登録時間、WebSocketの送受信量、エラー、同じ更新番号を受け取った参加者間の状態一致を報告します。死亡中などで拒否した入力の件数も記録します。ボットの入力検証は更新時間に含みます。通信量はWebSocketの本文であり、TLSなどのヘッダーを含みません。

`npm run benchmark:battlefield:core`は実通信を含まない補助測定です。実行結果と未確認事項は[検証報告](battlefield-validation.md)を参照してください。6体上限が実環境に適切かどうかは、補助測定だけでは判断しません。
