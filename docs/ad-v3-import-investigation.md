最初に必要なのは、本人が共有できる失敗JSONまたはそのコピー、出力元と取り込み先の利用バージョン、失敗時の表示、操作の順序と時刻である。続いて同期状態と保存・読込のどの段階で止まったかを確認する。ファイルを受け取れない場合は、本人の手元で解析・検証だけを行い、エラーの種類と表示を確認する。トークン、鍵、環境変数の値、接続情報を含む保存先全体は収集・ログ出力しない。

実行環境については、npmが起動でき、全依存がそろった書き込み可能な環境で `npm run test:ad` と `npm run check:completion` の成功を確認する必要がある。今回のNode直接実行の結果は上記の通り。報告書の必須見出し・本文・コマンド・未確認事項・失敗段階・段階別実測表は `sync.test.ts` の報告検査で確認し、成功した。

## 本番で確認する事項

本人が共有できる資料と表示結果だけを、安全に確認する。既存進捗を上書きする再試行は避ける。先に元の進捗を出力して保全し、失敗ファイルとは別に保持する。取り込みの案内だけで成功とせず、画面の進捗、同期の比較選択またはエラー表示、本人が選んだ進捗が保存後の再起動で残るかを確認する。既存進捗の保全が確認できるまでは、本番の保存内容を変更する確認は行わない。
